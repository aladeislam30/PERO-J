# Note to maintainers: #1162 checkpoint_state

Already implemented on main; no schema or code change needed. This issue can be closed.

- `indexer/migrations/0015_create_checkpoint_state.sql` creates `checkpoint_state` with `service_name VARCHAR PRIMARY KEY`, `last_ledger_sequence BIGINT`, `last_ledger_hash VARCHAR(64)` and `updated_at TIMESTAMP` (`IF NOT EXISTS`).
- `db.persistLedger()` in `indexer/src/db.js` inserts the ledger's events and upserts the checkpoint inside one `BEGIN`/`COMMIT`, so progress and event rows commit atomically; `db.getCheckpoint()` reads the last committed ledger for crash recovery.

Observation (out of scope here): `db.init()` applies only the inline `migrations` array in `indexer/src/db.js`; it does not read `indexer/migrations/*.sql`. Unless another path applies these files, `checkpoint_state` (and the `dlq_events` / later tables) will not exist on a fresh database.
